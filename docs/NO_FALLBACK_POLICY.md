# フォールバック禁止の方針

審査員が見るものは、すべて実際の API 呼び出しから来ていると信じられなければならない。失敗を代わりのデータで隠すと、「価格データも判定も本物」というピッチの土台が崩れる。

## 禁止すること

| 状況 | 禁止 | 必須 |
| --- | --- | --- |
| Vertex AI のモデルが使えない（404/403/クォータ） | 別のモデルやプロバイダー（Bedrock、OpenAI、モック）への切り替え | 例外を投げ、生のステータスとメッセージを表示 |
| Channel3 の呼び出しの失敗・タイムアウト | キャッシュ・モック・合成の価格を返す | 例外を投げ、生のステータスを表示。再試行は明示的に回数を決め、ログに残す |
| PayPal の注文・返金の失敗 | 返金済み扱いにする、返金を模擬する | 例外を投げ、失敗した試行を PayPal のエラーとともに台帳に記録 |
| 環境変数がない | 直書きの既定値で動かす | 起動時に変数名を示して止める |

プロバイダーは `.env` で明示的に選ぶ（LLM は `LLM_PROVIDER=vertex_gemini` が標準で `bedrock` も選べる、画像は `IMAGE_PROVIDER=vertex_gemini`）。Bedrock を意図して選ぶのは構わないが、Vertex AI が失敗したから自動で Bedrock に切り替えるのは禁止。`mock` プロバイダーは存在しない。

## フォールバックではないもの: 主張契約に書かれたルール

注文時に固定してハッシュを記録する契約の一部として、次の結果がある。

- **判定データが取れない → 買い手に有利に倒す。** これは判定ルールで、エラーからの回復ではない。台帳には、判定データの取得に失敗したこと（生のエラー付き）と、このルールを適用したことを記録する。
- **外れ値の価格を除外する。** 除外のルール（複数回の取得、店をまたいだ比較）は契約の一部で、除外した生データも台帳に残す。

## 画面

エラーの表示には、上流のサービス名、HTTP ステータス、エラーメッセージ、あればリクエスト／トレース ID を必ず出す。
